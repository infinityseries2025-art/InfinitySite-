# Настройка регистрации команд и защищённой админ-панели (Firebase)

Сайт по-прежнему статический и бесплатно хостится на GitHub Pages, но для
регистрации команд и входа в `admin.html` теперь используется **Firebase**
(бесплатный тариф **Spark** — карту привязывать не обязательно, лимитов
для турнирного сайта с лихвой хватит).

Настройка займёт 10–15 минут и делается один раз.

## 1. Создать проект Firebase

1. Зайди на https://console.firebase.google.com/ под своим Google-аккаунтом.
2. **Add project** → придумай название (например, `infinity-series-tournaments`) → далее можно отключить Google Analytics (не нужен) → **Create project**.

## 2. Включить Firestore (база данных заявок)

1. В меню слева: **Build → Firestore Database** → **Create database**.
2. Выбери любой регион (ближайший к твоей аудитории) → режим **Production mode** → **Enable**.
3. Когда база создastся, открой вкладку **Rules** и вставь туда следующий код целиком (заменив то, что там было), затем нажми **Publish**:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Организатор определяется по email — впиши сюда ТОТ ЖЕ email,
    // что указан в ADMIN_EMAIL в assets/js/firebase-config.js.
    // Это важно: теперь на сайте есть открытая самостоятельная регистрация
    // аккаунтов (account.html), поэтому "любой вошедший" — это уже не то
    // же самое, что "организатор". Без этой проверки обычный посетитель,
    // создавший себе аккаунт, смог бы менять расписание, турниры и новости
    // напрямую через консоль разработчика в браузере.
    function isAdmin() {
      return request.auth != null
             && request.auth.token.email != null
             && request.auth.token.email.lower() == 'ВСТАВЬ_EMAIL_АДМИНА_СЮДА'.lower();
    }

    // Модератор — обычный аккаунт, которому организатор выдал
    // role:"moderator" в его профиле (users/{uid}) через раздел
    // "Аккаунты игроков" в admin.html. Забаненный модератор прав не имеет.
    function isModerator() {
      return request.auth != null
             && exists(/databases/$(database)/documents/users/$(request.auth.uid))
             && get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == 'moderator'
             && get(/databases/$(database)/documents/users/$(request.auth.uid)).data.banned != true;
    }

    // "Персонал" — организатор или модератор. Модератору доступны
    // расписание, турниры (и добавление новых игр), заявки и новости,
    // но НЕ бан/удаление аккаунтов и НЕ выдача роли модератора —
    // это может только организатор (см. match /users/{uid} ниже).
    function isStaff() {
      return isAdmin() || isModerator();
    }

    match /teamApplications/{appId} {
      // Одобренные заявки видны всем (страница "Участники"),
      // остальные — только организатору и модераторам
      allow read: if isStaff() || resource.data.status == 'approved';

      // Любой посетитель может создать заявку, но только
      // в статусе "pending", с корректными полями и подтверждённым
      // согласием с правилами сайта (чекбокс на register.html).
      // roster — список игроков (каждый — { nickname, uid }, uid
      // заполняется автоматически, если ник совпал с зарегистрированным
      // аккаунтом); teamAvatar — необязательная картинка-аватар команды
      // в виде dataURL (см. ниже про хранение аватаров). Игра теперь
      // произвольная строка — список дисциплин можно пополнять из панели.
      allow create: if request.resource.data.status == 'pending'
                    && request.resource.data.teamName is string
                    && request.resource.data.teamName.size() > 0
                    && request.resource.data.teamName.size() <= 60
                    && request.resource.data.game is string
                    && request.resource.data.game.size() > 0
                    && request.resource.data.captainName is string
                    && request.resource.data.contact is string
                    && request.resource.data.roster is list
                    && request.resource.data.roster.size() > 0
                    && request.resource.data.roster.size() <= 10
                    && request.resource.data.agreedRules == true;

      // Менять статус (одобрить/отклонить) и удалять может организатор и модератор
      allow update, delete: if isStaff();
    }

    // Профили игроков: ник, аватар, описание, соцсети — заполняет
    // сам пользователь в личном кабинете (account.html). Документ id
    // всегда совпадает с uid из Firebase Authentication.
    // Читать может кто угодно (без этого не заработают ни подсказка
    // ников на регистрации команды, ни ссылки на профиль в "Участниках"
    // для гостей, которые не вошли в аккаунт).
    // Поля role (модератор) и banned (бан) может менять только
    // организатор — обычный пользователь не может выдать роль себе
    // сам или снять с себя бан, отредактировав профиль.
    match /users/{uid} {
      allow read: if true;

      allow create: if request.auth != null && request.auth.uid == uid
                    && request.resource.data.nickname is string
                    && request.resource.data.nickname.size() > 0
                    && request.resource.data.nickname.size() <= 30
                    && !('role' in request.resource.data)
                    && !('banned' in request.resource.data);

      allow update: if isAdmin()
                    || (request.auth != null && request.auth.uid == uid
                        && request.resource.data.nickname is string
                        && request.resource.data.nickname.size() > 0
                        && request.resource.data.nickname.size() <= 30
                        && request.resource.data.get('role', null) == resource.data.get('role', null)
                        && request.resource.data.get('banned', null) == resource.data.get('banned', null));

      // Удалить профиль (карточку "Аккаунты игроков" в панели) может
      // только организатор. Сам вход (email в Firebase Authentication)
      // это не удаляет — см. примечание в тексте ниже.
      allow delete: if isAdmin();
    }

    // Расписание матчей — читает весь сайт (главная, "Расписание"),
    // редактирует организатор и модератор через admin.html
    match /schedule/{matchId} {
      allow read: if true;
      allow write: if isStaff();
    }

    // Команды: рейтинг Эло, победы/поражения, титулы. Читает весь сайт
    // (страница "Турниры"), пишет организатор/модератор (начисление Эло
    // и титулов происходит автоматически при завершении турнира).
    match /teams/{teamId} {
      allow read: if true;
      allow write: if isStaff();
    }

    // Турниры и турнирные сетки — читает весь сайт, создаёт/меняет/удаляет
    // организатор и модератор.
    match /tournaments/{tournamentId} {
      allow read: if true;
      allow write: if isStaff();
    }

    // Новости — читает весь сайт (главная, "Новости"),
    // добавляет/редактирует/удаляет организатор и модератор.
    match /news/{newsId} {
      allow read: if true;
      allow write: if isStaff();
    }

    // Настройки сайта — сейчас только список дополнительных игр
    // (settings/games, поле list), которые организатор/модератор
    // добавляют прямо из панели создания турнира.
    match /settings/{docId} {
      allow read: if true;
      allow write: if isStaff();
    }
  }
}
```

Это правило — главная защита: гость может только *создать* заявку со
статусом «pending», ничего чужого читать или менять он не может.
Любой человек может создать себе обычный аккаунт через `account.html`
(это отдельная функция — просто вход/личный кабинет), но одобрять и
отклонять заявки, редактировать расписание, создавать турниры, начислять
Эло и публиковать новости может организатор (`ADMIN_EMAIL`) и любой
аккаунт, которому организатор выдал роль модератора.

### Новое: модераторы, свои игры и баны аккаунтов

- **Модератор.** В `admin.html` появился раздел «Аккаунты игроков» (виден
  только организатору). Там можно нажать «Сделать модератором» у любого
  зарегистрированного аккаунта — после этого человек сможет войти в
  `admin.html` тем же email/паролем, каким входит в свой обычный кабинет,
  и получит доступ к расписанию, турнирам, заявкам и новостям. Выдавать
  роль модератора и снимать её может только организатор.
- **Свои игры.** В блоке «Создать турнир» есть поле «Новая дисциплина» —
  организатор или модератор может добавить любую игру (например,
  Valorant), она сразу появится в списках игр на регистрации, в
  расписании и при создании турниров.
- **Бан и удаление аккаунта.** В том же разделе «Аккаунты игроков» можно
  забанить аккаунт (он не сможет войти в личный кабинет, пока бан не
  снят) или удалить его профиль (ник/аватар/описание). Важное
  ограничение бесплатного тарифа: сам вход в Firebase Authentication
  (связку email+пароль) client-side код удалить не может — это операция
  уровня Admin SDK, которая на статическом сайте без сервера недоступна.
  Если нужно и полностью заблокировать сам вход — зайди в Firebase
  Console → Authentication → Users, найди аккаунт по email и нажми
  «Disable user» (или «Delete user», если нужно удалить совсем).

### Про аватарки (профиль игрока и команда)

Аватарки не используют Firebase Storage (отдельный платный/настраиваемый
сервис) — картинка сразу в браузере сжимается и уменьшается до небольшого
размера, превращается в текстовую строку (`dataURL`) и сохраняется прямо
в документе Firestore рядом с остальными полями (`avatar` — у профиля,
`teamAvatar` — у заявки команды). Это осознанное упрощение: не нужна
дополнительная настройка, но у Firestore есть жёсткий лимит — один
документ не может весить больше 1 МБ, поэтому сильно большие/несжатые
изображения загрузить не получится (сайт сам ужимает картинку перед
отправкой, обычный аватар весит не больше 40–80 КБ).

О защите формы регистрации от ботов: страница `register.html`
дополнительно использует клиентские приёмы (скрытое honeypot-поле,
задержка перед отправкой, математическая проверка, ограничение частоты
с одного браузера) — это не заменяет правила Firestore выше, а снижает
количество спама ещё до похода в базу. Если спама будет много, можно
дополнительно подключить бесплатный Firebase App Check с reCAPTCHA v3
(Build → App Check в консоли) — это отдельная настройка, не обязательная
для запуска.

## 3. Включить вход по email/паролю и завести свой аккаунт

1. В меню слева: **Build → Authentication** → **Get started**.
2. На вкладке **Sign-in method** включи провайдер **Email/Password** → **Save**.
3. Перейди на вкладку **Users** → **Add user** → укажи свой email и придумай
   пароль. Это будет аккаунт организатора.
4. Открой `assets/js/firebase-config.js` и впиши этот же email в константу
   `ADMIN_EMAIL` (замени `"ВСТАВЬ_СЮДА_EMAIL_АДМИНА"`). Именно по этому
   email сайт понимает, что вошедший человек — организатор, и либо
   пускает его в `admin.html`, либо открывает ему обычный личный кабинет.
5. Впиши тот же email в функцию `isAdmin()` в правилах Firestore — см. шаг 2
   выше (замени `'ВСТАВЬ_EMAIL_АДМИНА_СЮДА'`).

Обычные посетители теперь могут сами создавать себе аккаунты на странице
`account.html` (просто email и пароль — личный кабинет без каких-либо
дополнительных прав). Организатором может быть только тот, чей email
совпадает с `ADMIN_EMAIL` — если понадобится добавить второго
администратора, заведи ему пользователя в **Authentication → Users** и
пропиши второй email проверкой в `ADMIN_EMAIL`/`isAdmin()` (например,
через `in ['email1', 'email2']`).

## 4. Разрешить домен сайта для входа

1. Всё там же, в **Authentication → Settings → Authorized domains** → **Add domain**.
2. Добавь свой домен GitHub Pages, например `имя-пользователя.github.io`
   (без `https://`). Иначе вход в админку с сайта не сработает.

## 5. Скопировать ключи конфигурации в сайт

1. Нажми на шестерёнку рядом с **Project Overview** → **Project settings**.
2. В блоке **Your apps** нажми на иконку `</>` (Web) → придумай название
   приложения → **Register app** (Hosting подключать не нужно).
3. Появится блок `firebaseConfig` с ключами — скопируй значения полей
   `apiKey`, `authDomain`, `projectId`, `storageBucket`,
   `messagingSenderId`, `appId`.
4. Открой файл `assets/js/firebase-config.js` в репозитории на GitHub
   (карандаш «Edit») и вставь свои значения вместо `"ВСТАВЬ_СЮДА"` →
   **Commit changes**.

Эти ключи не секретные (это нормально для Firebase — они просто говорят
браузеру, к какому проекту подключаться), реальная защита данных — это
правила Firestore из шага 2.

## 6. Готово — как это работает

- **`account.html`** — публичная страница «Аккаунт»: любой посетитель
  может создать себе обычный аккаунт (email + пароль) или войти в уже
  существующий. Обычный аккаунт открывает простой личный кабинет
  (email + кнопка «Выйти») и никаких особых прав не даёт. Если ввести на
  этой же странице email и пароль администратора — сайт сам, без всяких
  дополнительных действий, перенаправит на `admin.html`.
- **`register.html`** — публичная форма. Любой человек может подать
  заявку на команду (не требует аккаунта), она попадает в базу со
  статусом «pending».
- **`participants.html`** — публичный список команд, но показывает
  только те, что ты одобрил.
- **`admin.html`** — при заходе просит email и пароль; открывает панель
  только если email совпадает с `ADMIN_EMAIL`. После входа появляется
  список всех заявок с кнопками «Одобрить» / «Отклонить» / «Удалить»,
  ниже — редактор расписания (сохраняет изменения в Firebase сразу, без
  скачивания файлов и коммитов в git), ещё ниже — создание турниров:
  вводишь название и список команд, сайт сам строит сетку на выбывание;
  дальше просто нажимаешь «Победа» у нужной команды в каждом матче.
  Когда сетка доходит до финала, кнопка «Завершить турнир» пересчитывает
  рейтинг Эло всем участникам турнира и выдаёт победителю титул вида
  «Обладатели трофея {название турнира}» — это видно всем на странице
  `tournaments.html`. В самом низу панели — раздел «Новости»: форма
  добавления новости и список уже опубликованных с кнопками
  «Редактировать» / «Удалить». Новости сразу появляются на странице
  `news.html` и в блоке новостей на главной, без правки JSON-файлов
  и коммитов в git.
- **`tournaments.html`** — публичная страница: сетки всех турниров и
  таблица рейтинга Эло по каждой игре, с титулами команд.

Если понадобится добавить второго администратора — заведи ещё одного
пользователя в **Authentication → Users** и добавь его email в проверку
`ADMIN_EMAIL` (`firebase-config.js`) и `isAdmin()` (правила Firestore),
например через `in ['email1@example.com', 'email2@example.com']`.

## Лимиты бесплатного тарифа

Spark-тариф Firestore включает 50 000 чтений и 20 000 записей в день —
для турнирного сайта с заявками команд этого более чем достаточно.
Если когда-нибудь трафик вырастет так, что лимит будет мало, Firebase
сам покажет предупреждение в консоли задолго до проблем.
