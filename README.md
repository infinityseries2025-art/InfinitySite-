# Infinity Series Tournaments — сайт турниров (CS2 / Dota 2 / PUBG)

Готовый статический сайт: главная, новости, команда организации, расписание,
турниры с сеткой и рейтингом Эло, регистрация команд, список участников,
контакты. Хостится бесплатно на GitHub Pages. Расписание, регистрация команд,
турниры и вход в админ-панель работают через бесплатный бэкенд Firebase —
подробная настройка в файле [`FIREBASE_SETUP.md`](./FIREBASE_SETUP.md)
(сделать нужно один раз, займёт 10–15 минут).

## Структура проекта

```
index.html          — главная
news.html            — новости
participants.html     — публичный список команд, прошедших модерацию
register.html          — публичная форма регистрации команды (с защитой от ботов)
account.html             — вход/регистрация обычного аккаунта посетителя;
                            вход под данными администратора автоматически
                            перенаправляет на admin.html
team.html                — команда организации (организаторы, судьи и т.д.)
schedule.html              — расписание матчей (с фильтром по играм, из Firebase)
tournaments.html             — турнирные сетки + таблица рейтинга Эло
contacts.html                  — контакты + форма обратной связи
admin.html                       — вход организатора + модерация заявок +
                                    редактор расписания + создание турниров
                                    (не в меню сайта)

assets/css/style.css     — все стили и цветовая палитра
assets/js/main.js         — логика: подстановка лого/фона, вывод данных,
                             расписание (читает Firebase)
assets/js/tournament-shared.js — сетка на выбывание, формула Эло, рендер сетки
                                  (общий код для admin.html и tournaments.html)
assets/js/admin.js         — редактор расписания + создание/ведение турниров
assets/js/admin-auth.js     — вход организатора (только по ADMIN_EMAIL) и
                                модерация заявок команд
assets/js/account.js         — регистрация/вход обычного аккаунта,
                                редирект на admin.html для администратора
assets/js/register.js        — отправка заявки на регистрацию (honeypot,
                                time-trap, капча, ограничение частоты)
assets/js/participants.js     — вывод одобренных команд
assets/js/tournaments.js       — публичный рендер сеток и таблицы Эло
assets/js/firebase-config.js    — сюда вставляешь свои ключи Firebase
assets/images/                    — сюда кладёшь свои картинки

data/config.json    — название сайта, пути к лого/фону, контакты
data/news.json        — запасной вариант новостей: используется, только
                         пока в Firebase (коллекция "news") ещё нет ни
                         одной опубликованной новости. Как только
                         добавишь новость через admin.html — сайт
                         полностью переходит на данные из Firebase
data/team.json         — состав команды организаторов
data/schedule.json      — больше не используется сайтом (оставлен как образец
                           формата матча); расписание теперь хранится в Firebase

FIREBASE_SETUP.md   — пошаговая настройка Firebase (регистрация, расписание,
                       турниры, рейтинг Эло, вход организатора)
```

## Как загрузить логотип и фон

Просто положи файлы в `assets/images/` с этими именами (заменив старые):

- `assets/images/logo.png` — логотип турнира (он же кнопка на главную в шапке)
- `assets/images/background.jpg` — фон сайта
- `assets/images/favicon.png` — иконка вкладки браузера

Ничего в коде менять не нужно — если файл появился, сайт сам его подхватит.
Если файла нет — покажется нейтральная заглушка, сайт не сломается.

Название сайта, подпись под лого и контакты (email/телефон/telegram/discord/vk)
редактируются в `data/config.json`.

## Как изменить расписание (без git)

Открой `admin.html` (страница не отображается в меню сайта — это служебная
страница только для организатора), войди своим аккаунтом и редактируй таблицу
матчей прямо там. Каждое изменение поля сохраняется в Firebase сразу же —
сайт подхватывает новые данные при следующей загрузке страницы «Расписание».
Скачивать файлы и коммитить их в GitHub больше не нужно.

Новости теперь добавляются и редактируются прямо в `admin.html`, в разделе
«Новости» — так же, как расписание, без правки файлов и коммитов в git.
Состав команды (`data/team.json`) по-прежнему редактируется прямо в файле
на GitHub, по образцу существующих записей — этот раздел меняется редко,
поэтому остался простым JSON-файлом.

## Аккаунты посетителей и вход администратора

Страница `account.html` (пункт меню «Аккаунт») даёт любому посетителю
создать себе простой аккаунт (email + пароль) или войти в уже созданный.
После входа открывается личный кабинет, где можно задать **ник, аватар,
описание и ссылки на соцсети (Telegram/Discord/VK/Twitch)** — это
публичный профиль, он сохраняется в Firestore (`users/{uid}`).

Через ту же самую форму входа заходит и администратор: если введённый
email совпадает с `ADMIN_EMAIL` (`assets/js/firebase-config.js`), сайт
автоматически перенаправляет на `admin.html`. Подробная настройка —
в [`FIREBASE_SETUP.md`](./FIREBASE_SETUP.md).

### Привязка аккаунтов в заявке на регистрацию команды

На странице `register.html` состав команды вводится построчно (кнопка
«+ Добавить игрока»). Для каждого игрока и капитана можно просто вписать
ник — а если этот ник совпадает с ником зарегистрированного на сайте
аккаунта, поле подскажет его автодополнением, и заявка автоматически
прикрепит `uid` этого аккаунта. После одобрения заявки на странице
«Участники» такие ники становятся кликабельной ссылкой на публичный
профиль игрока (`account.html?u=UID`) — так же ссылка появляется на
капитане, если он тоже привязан. Там же, на регистрации, можно загрузить
аватар для самой команды.

## Турниры и рейтинг Эло

В `admin.html`, в разделе «Турниры»:

1. Указываешь название турнира (например, «IST Season 1»), игру и список
   команд — по одной на строке. Сайт сам строит сетку на выбывание (если
   команд не степень двойки — недостающие места автоматически становятся
   технической победой соперника).
2. По ходу турнира в каждом матче нажимаешь «Победа» у нужной команды —
   сетка сама достраивает следующий раунд.
3. Когда сетка доходит до финала и в нём определился победитель, появляется
   кнопка «Завершить турнир и наградить победителя». По нажатию:
   - каждой паре команд в каждом сыгранном матче турнира пересчитывается
     рейтинг Эло (начальный рейтинг новой команды — 1000, K-фактор — 32);
   - команда-победитель турнира автоматически получает титул
     «Обладатели трофея {название турнира}» (например, «Обладатели трофея
     IST Season 1»).

Всё это сразу видно всем на публичной странице `tournaments.html` — сетки
турниров, титулы команд и таблица рейтинга Эло по каждой игре.

## Как выложить на GitHub Pages

1. Создай новый репозиторий на GitHub и загрузи в него все файлы этой папки
   (через веб-интерфейс «Add file → Upload files» или через git).
2. Зайди в репозиторий → **Settings → Pages**.
3. В разделе **Build and deployment** выбери **Source: Deploy from a branch**,
   ветку `main` и папку `/ (root)`. Сохрани.
4. Через 1–2 минуты сайт будет доступен по адресу вида
   `https://имя-пользователя.github.io/имя-репозитория/`.

Дальше любое изменение файлов в репозитории (лого, фон, новости, состав
команды) автоматически обновляет сайт — редактировать код не нужно.
Расписание и турниры правятся отдельно, через `admin.html` (см. выше) —
для них никаких изменений в репозитории делать не нужно.

## Защита регистрации от ботов

Форма на `register.html` работает без сторонних сервисов, но включает
несколько лёгких клиентских проверок: скрытое honeypot-поле, минимальную
задержку перед отправкой, простую математическую проверку и ограничение
частоты отправки с одного браузера. Подробнее — в `FIREBASE_SETUP.md`,
там же описано, как при необходимости добавить Firebase App Check с
reCAPTCHA v3 для более серьёзной защиты.

## Цвета и шрифт

Основной цвет фона — тёмно-серый `#1C1D21`, акцент — розовый `#FFACBC`,
шрифт — **Raleway**. Все цвета собраны в начале файла `assets/css/style.css`
в блоке `:root`, их можно поменять там же одним местом, если понадобится.
